# 管线搭建 · 抗氧化方向（READY，可产预计算 construct）

> 写于 2026-09-05。本文是「多管线搭建方案.md」在**抗氧化方向**的落地版。
> 核心前提：所有工具分数已在 20,248,885 条肽库上预计算完毕，本方向不再跑分，只做**选取**。
> 因 MHCflurry 等长受限工具的真实覆盖缺口，全流程遵循**可空缺性原则**：分数缺失（NULL）永不淘汰肽，只标记为「未评估」。

## 0. 数据前提与各分数的覆盖度

本方向用到的分数，以及它们在 20M 库上的实际覆盖率（覆盖度决定空值率）：

| 分数列（建议名） | 工具 | 覆盖 | 空值率 | 本方向角色 |
|---|---|---|---|---|
| `toxinpred3` | ToxinPred3 | 全量 20,248,885 | ~0% | 安全硬门控（full） |
| `hemopi2` | HemoPI2 | 仅 500,000 抽样 | **~97.5% NULL** | 安全·溶血（present-and-failing） |
| `mhcflurry` | MHCflurry | 仅长度 5–15 aa（134,888） | **~99.3% NULL** | 安全·MHC-I（参考，非必备） |
| `netmhcipan_pctrank` | NetMHCIIpan | 14.8M（10–30 aa） | ~27% NULL（短肽） | 安全·MHC-II（软，%Rank） |
| `aopxsvm` | AOPxSVM | 全量 20,248,883 | ~0% | **功能主排序** |
| `anoxpepred_frs` | AnOxPePred | 仅 500,000 抽样 | ~97.5% NULL | 功能·辅助确认（仅 500K 内有值） |
| `plm4cpps` | pLM4CPPs | 全量 ~20M | ~0% | 可开发性·穿膜（软） |
| `algpred2` | AlgPred2 | 全量 ~20M | ~0% | 安全·致敏（软） |
| `bepipred` | BepiPred-3.0 | 全量 20M | ~0% | 安全·B 细胞表位（软） |
| `aggrescan_a3v` | 一维 AGGRESCAN | 可实时算（公式） | 0% | 可开发性·聚集（软，可选） |

**覆盖度带来的直接结论**：`hemopi2` 与 `mhcflurry` 对绝大多数肽是空的，因此它们**不能作硬门控**（否则会误杀 97–99% 的肽）。它们在本流程里降级为「参考/软信号」——分数存在且超标才标记风险，不存在则放行并标记未评估。真正全覆盖的硬门控只有 `toxinpred3`；功能主排序 `aopxsvm` 也是全覆盖，所以抗氧化方向的核心选取完全跑得通。

## 1. 安全门控（可空缺性原则）

**统一规则**：`某分数存在 且 超过阈值` 才淘汰该肽；`分数为 NULL` 一律放行（但记入未评估标记）。这一条对全部工具统一适用，是「可空缺性」的精确表达。

**PostgreSQL 选取（安全 + 功能候选池）**：

```sql
-- 第一步：安全门控（可空缺）+ 抗氧化主排序候选池
-- 取「通过安全 且 AOPxSVM 处于全库前 10%」的肽作为候选，再交 Python 做加权排名
WITH p90 AS (
  SELECT percentile_cont(0.90) WITHIN GROUP (ORDER BY aopxsvm) AS cutoff
  FROM igem_peptides
)
SELECT
  id, sequence, length, source,
  aopxsvm, anoxpepred_frs,
  toxinpred3, hemopi2, mhcflurry, netmhcipan_pctrank,
  plm4cpps, algpred2, bepipred,
  -- 软风险标记（不淘汰，仅标注）
  CASE WHEN hemopi2        IS NOT NULL AND hemopi2        >= 0.50 THEN 'HEMO'        END AS flag_hemo,
  CASE WHEN mhcflurry      IS NOT NULL AND mhcflurry      >= 0.87 THEN 'MHC_I_SB'     END AS flag_mhci,
  CASE WHEN netmhcipan_pctrank IS NOT NULL AND netmhcipan_pctrank <= 2 THEN 'MHC_II_SB' END AS flag_mhcii,
  -- 覆盖度标记（供人工复核 / 未来补算）
  (hemopi2 IS NOT NULL)        AS assessed_hemo,
  (mhcflurry IS NOT NULL)      AS assessed_mhci
FROM igem_peptides, p90
WHERE (toxinpred3 IS NULL OR toxinpred3 < 0.38)     -- 毒性硬门控（full，极少 NULL）
  AND (hemopi2    IS NULL OR hemopi2    < 0.50)     -- 溶血：存在且失败才淘汰
  AND aopxsvm >= p90.cutoff                       -- 功能主排序：全库前 10%
ORDER BY aopxsvm DESC;
```

说明：`mhcflurry >= 0.87` 对应论文「IC50 < 50 nM 强结合子」的分界（MHCflurry wiki：强结合子 score ≈ 0.87+）。它**不在 WHERE 里淘汰**，只在 SELECT 里标记，因为 99.3% 是 NULL，淘汰会清空库。

## 2. 功能排序：AOPxSVM 分位 Top-K（主）+ AnOxPePred（辅）

AOPxSVM 在 20M 上把 72.83% 判为阳性（0.5 阈值失真），所以**绝不能用 0.5 当 cutoff**，而用全库分位。`percentile_cont(0.90)` 已算出 P90  cutoff，上一步 WHERE 已取前 10%。这 10% 是抗氧化高先验候选池。

AnOxPePred 的 FRS 分数只在 500K 抽样里有值，因此只能作为**辅助确认**：在同一候选池内，若某肽恰好有 `anoxpepred_frs >= 0.5`，给它加一个「保守确认」标记、优先排序；没有该分数的肽不因此被降权（因为 97.5% 都没有，降权会系统性惩罚大多数）。即 AnOxPePred 是「加分项」而非「门槛」。

**Python（pandas）补充排序**：

```python
import pandas as pd, numpy as np

df = pd.read_sql(query_above, conn)   # 上一步 SQL 的结果

# 功能分（只用一次：决定 Top/Bottom 通道）
df['func_score'] = df['aopxsvm']
# AnOxPePred 辅助确认（仅 500K 内有值，作为加分）
df['anox_confirm'] = (df['anoxpepred_frs'].fillna(0) >= 0.5).astype(int)

# 通道划分：func_score 在全库前 10% 即 Top 通道（已在 SQL 保证），这里再细分 Top/Bottom
# 取 Top 150 候选 + Bottom 100 对照（Bottom = 池内排名末位，用于对照）
pool_sorted = df.sort_values('aopxsvm', ascending=False).reset_index(drop=True)
top150   = pool_sorted.head(150)
bottom100 = pool_sorted.tail(100)
```

## 3. 可开发性加权（软，进入综合分）

抗氧化候选在功能上已达标，下一步用可开发性 + 安全软信号做**排名**（不淘汰）。用到的分量：

- `plm4cpps`（穿膜倾向，越高越好）——外用/纳米载体/微针递送时权重调高。
- `algpred2`（致敏，越低越好）——取反向后进分。
- `bepipred`（B 细胞表位连续分，越低越好）——取反向后进分。
- `aggrescan_a3v`（一维聚集倾向，a3v 标度，越负越可溶；越高越促聚集）——取反向后进分。该值按序列公式实时算，覆盖 100%，可作为肽级聚集代理（替代需三维结构的 A3D）。

**温莎化标准差（Winsorized std）权重**：先用分位把每个分量里极端的离群值「缩尾」（如低于 5% 分位、高于 95% 分位的值压到边界），再算标准差；用这个被缩尾后的标准差衡量该分量的**区分度**——区分度越高（分数越能拉开候选），权重越大。这样权重由数据自己决定，不写死（对齐 README 铁律）。仅保留人工系数 α（默认 1.0）。

```python
def winsorized_std(s, lo=0.05, hi=0.95):
    return s.clip(s.quantile(lo), s.quantile(hi)).std()

def to_component(s, higher_better=True):
    # 归一化到 0–1，方向统一为「越高越好」
    n = (s - s.min()) / (s.max() - s.min())
    return n if higher_better else 1 - n

comps = {
    'cpp':      to_component(df['plm4cpps'], True),
    'sens':     to_component(df['algpred2'], False),
    'epitope':  to_component(df['bepipred'], False),
    'agg':      to_component(df.get('aggrescan_a3v'), False),
}
weights = {k: winsorized_std(v) for k, v in comps.items()}
weights = {k: w / sum(weights.values()) for k, w in weights.items()}   # 归一化
```

## 4. 综合分与递送调权（Python）

综合分只在 Top 通道内排名（功能分已「用过一次」决定通道，不再进综合分）。综合分 = Σ 分量权重 × 分量值，再乘 α。递送方式改变权重（外用/纳米/微针/注射四套，对齐 README 前端规则）：

```python
# 递送方式权重乘数（相对基准 1.0）
DELIVERY = {
    ' topical':  {'cpp':1.4, 'sol':1.3, 'thermal':0.7, 'immuno':'normal'},
    'nano':      {'cpp':0.7, 'sol':1.4, 'thermal':1.0, 'immuno':'normal'},
    'microneedle':{'cpp':1.0,'sol':1.4, 'thermal':1.4, 'immuno':'normal'},
    'injection': {'cpp':1.0, 'sol':1.0, 'thermal':1.0, 'immuno':'tight'},   # 注射免疫阈值收紧到 0.35
}

def composite(row, comps, weights, mult):
    return sum(weights[k] * comps[k][row.name] * mult.get(k, 1.0) for k in weights) * ALPHA

for d, mult in DELIVERY.items():
    df[f'composite_{d}'] = [composite(i, comps, weights, mult) for i in df.iterrows().__self__()]
```

> 注：`immuno` 收紧在注射下的处理：对 `flag_mhci` / `flag_mhcii` 非零的肽，注射递送时直接判 `failed_safety`（综合分置 0、不参与排名）；其余递送按软标记处理。这样「注射收紧到 0.35」落到了选取逻辑里。
