## 1. 安全门控（可空缺性原则，与抗氧化相同）

统一规则：分数**存在且超过阈值**才淘汰；**NULL 一律放行**并标记未评估。

**PostgreSQL 选取（安全 + 功能候选池）**：

```sql
-- 抗菌方向：安全门控（可空缺）+ AMPlify 主排序候选池
SELECT
  id, sequence, length, source,
  amplify,
  toxinpred3, hemopi2, mhcflurry, netmhcipan_pctrank,
  plm4cpps, algpred2, bepipred,
  CASE WHEN hemopi2           IS NOT NULL AND hemopi2           >= 0.50 THEN 'HEMO'     END AS flag_hemo,
  CASE WHEN mhcflurry         IS NOT NULL AND mhcflurry         >= 0.87 THEN 'MHC_I_SB'  END AS flag_mhci,
  CASE WHEN netmhcipan_pctrank IS NOT NULL AND netmhcipan_pctrank <= 2 THEN 'MHC_II_SB' END AS flag_mhcii,
  (hemopi2   IS NOT NULL) AS assessed_hemo,
  (mhcflurry IS NOT NULL) AS assessed_mhci
FROM igem_peptides
WHERE (toxinpred3 IS NULL OR toxinpred3 < 0.38)   -- 毒性硬门控
  AND (hemopi2    IS NULL OR hemopi2    < 0.50)   -- 溶血：present-and-failing
  AND (amplify    IS NULL OR amplify    >= 0.50)  -- 功能：AMPlify 原版阈值 0.5；NULL 不淘汰（覆盖待确认）
ORDER BY amplify DESC;
```

> 若 AMPlify 实际仅覆盖子集，`amplify IS NULL` 的肽会全部保留进候选——这是可空缺性原则的必然结果。上线前建议先 `SELECT count(*) FROM igem_peptides WHERE amplify IS NOT NULL` 确认覆盖率；若覆盖率低，应先用 AMPlify 把全 20M 补算一遍（原版是成熟 TensorFlow/Keras 模型，部署成本最低），再将其升为真正功能门控。

## 2. 功能排序：AMPlify ≥ 0.5（主）

AMPlify 原版在平衡测试集 AUC 0.9848、特异度 0.9557，是四个方向里**唯一干净可用的功能主排序器**。它的已知偏见：偏袒「阳离子两亲性短肽（尤其蛙类来源）」，负类训练用的是长链球状蛋白——所以它擅长「典型数据库 AMP vs 普通长蛋白」，不擅长「形似 AMP 但无活性」的难例。本方向直接用 `amplify >= 0.5` 取候选池，再按分数降序排 Top-K。

## 3. 可开发性加权（软，与抗氧化同套）

抗菌候选在功能上达标后，用以下分量做排名（不淘汰）：

- `plm4cpps`（穿膜，越高越好）——外用/纳米/微针递送权重调高。
- `algpred2`（致敏，越低越好）——反向进分。
- `bepipred`（B 细胞表位，越低越好）——反向进分。
- `aggrescan_a3v`（聚集，越负越可溶）——反向进分，实时算、全覆盖。

权重用**温莎化标准差**（先把极端值缩尾再算标准差，用缩尾后的标准差衡量区分度，区分度高的分量自动升权），归一化后得各分量权重，仅留人工系数 α（默认 1.0）。代码与抗氧化方向第 3 节完全相同，此处不重复。
