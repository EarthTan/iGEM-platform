## 1. 提案原样照搬的可行性：5 处偏差（vs 提案 §1–§4）

| # | 提案假设 | DB 实际 | 工程修正 |
|---|---|---|---|
| 1 | `igem_peptides` 宽表，9 列分数 | `peptide_enrichment` **长表** `(peptide_id, tool, score, ...)` | 提案 §1 SQL 全部要重写 |
| 2 | `aip_v5`（L1）和 `aip_esm2`（L2 主信号）全量 | **DB 实际 0 行**（check_score_coverage_aip 已核对）| **L1→L2 级联完全退化**为 imfp_lg_AIP 单信号排序；用 imfp_lg_AIP 既当 L1 候选池 cutoff，又当 L2 主排序 |
| 3 | `blsam_tip_lr/gbm`（抗黑素跨功能去混淆）全量 | DB 实际 0 行（与 antimelanin v1 一致）| 跨功能去混淆只用 6 个通道（抗氧化 + 抗菌 + iMFP-LG 五通道） |
| 4 | `netmhcipan_pctrank` 在 peptide_enrichment 中 | DB 实际是独立表 `netmhc_score`（1.475 亿行·132 allele·14.8M 独立肽） | select.py 加 `enrich_top_bottom_with_netmhciipan`：从 250 个 sequence 在独立表查 + peptide 粒度聚合 |
| 5 | `bepipred` 全覆盖 | DB 实际 `tool='bepipred3'`（拼写差异）| 工程上重命名为 bepipred3 |

工程上的修正路线：

1. 候选池 SQL 改用长表查询（`tool='imfp_lg_AIP' AND score >= p90`，内联 `length BETWEEN 11 AND 30` 走 peptides_length_idx）
2. 不建宽表，沿用 antibacterial 的"先选 Top250 id，再主键 enrich"的策略
3. 缺失的 tool 列按"可空缺性原则"放行，记前端"未评估"
4. tool 名差异通过工程化重命名解决（bepipred → bepipred3）
5. **netMHCIIpan 从独立表接入**，保留肽粒度聚合而非全表拉取
6. **AIP 主排序退化为单信号**：imfp_lg_AIP 既是候选池 cutoff，又是综合分主信号

## 3. 提案 SQL 在长表上的重写

提案 §1 给出的候选池 SQL：

```sql
SELECT
  id, sequence, length, source,
  aip_v5, aip_esm2, imfp_lg_aip,
  imfp_lg_acp, imfp_lg_adp, imfp_lg_ahp, imfp_lg_amp,
  aopxsvm, amplify, blsam_tip_lr, blsam_tip_gbm,
  plm4cpps, algpred2, bepipred,
  toxinpred3, hemopi2, mhcflurry, netmhcipan_pctrank,
  ...
FROM igem_peptides
WHERE length BETWEEN 11 AND 30
  AND (toxinpred3 IS NULL OR toxinpred3 < 0.38)
  AND (hemopi2    IS NULL OR hemopi2    < 0.50);
```

不能直接执行，因为：

- 表名 `igem_peptides` 实际是 peptides（只有元数据）；分数在 peptide_enrichment。
- 18 个相关子查询 PG planner 无法去相关 → 实测 30+ 分钟无法收敛。
- DB 里 `aip_v5` / `aip_esm2` / `blsam_tip_lr/gbm` / `netmhcipan_pctrank` 实际不存在。
- `bepipred` 实际名为 `bepipred3`；`imfp_lg_aip` 实际名为 `imfp_lg_AIP`（大小写敏感）。

**重写后**：

```sql
WITH p90 AS (
    SELECT percentile_disc(0.90) WITHIN GROUP (ORDER BY score)::float8 AS cutoff
      FROM peptide_enrichment
     WHERE tool = 'imfp_lg_AIP' AND score IS NOT NULL
)
SELECT e.peptide_id, e.score AS aip_imfp, e.label AS aip_imfp_label
  FROM peptide_enrichment e, p90
 WHERE e.tool = 'imfp_lg_AIP'
   AND e.score >= p90.cutoff
   AND e.peptide_id IN (SELECT id FROM peptides WHERE length BETWEEN 11 AND 30)
ORDER BY e.score DESC
```

**单 SQL 15.6 秒**出 2,024,889 行（候选池 = 全库前 10%）。

注意 SQL 内联了 length 过滤（走 peptides_length_idx），避免外 JOIN 时 20M 行无索引扫描。

## 4. 关键工程决策：250-id 主键 enrich + netmhc_score 独立查 + 跨功能去混淆

### 4.1 为什么不能拉全表 enrich

候选池 2.02M 行，对每个 tool 用 `WHERE peptide_id = ANY(%s)` 查询 2M 个 peptide_id：

- 走 `peptide_enrichment_pk` 主键，理论应该快；
- 实测：planner 选 bitmap heap scan，**VACUUM 缺失时单 tool 30+ 分钟**。

### 4.2 解决方案：250-id 主键查询（沿用 antibacterial）

候选池里只需要 Top 150 + Bottom 100 = 250 个肽做最终落库。**对 250 id 查 12 个 tool 列**（imfp_lg_AIP 已在候选池，剩 12 个 tool）：

```python
for tool in tools:
    sql = f"SELECT peptide_id, score FROM peptide_enrichment " \
          f"WHERE tool = '{tool}' AND peptide_id = ANY(%s)"
    cur.execute(sql, ([250 ids],))
```

走主键 `(peptide_id, tool)`，单 tool 查询 **0–15s**（其中 `bepipred3` 较慢——14.8s；其他 tool 都在 0.5s 内）。

### 4.3 netMHCIIpan 独立查询

netMHCIIpan 分数在独立表 `netmhc_score`，肽 × allele 粒度存储（1.475 亿行）。**不能**在 peptide_enrichment 中拉取（该表中不存在）。

接入路径（select.py `enrich_top_bottom_with_netmhciipan`）：

```sql
-- 先从 peptides 拿 sequence（peptide_id → sequence，毫秒）
SELECT id, sequence, length FROM peptides WHERE id = ANY([250 ids])

-- 再从 netmhc_score 按 peptide 粒度聚合（peptide 上有索引，~5 秒）
SELECT peptide,
       MIN(rank_pct)                                  AS min_rank_pct,
       MIN(rank_pct) FILTER (WHERE bind_level='SB') AS min_sb_rank_pct,
       BOOL_OR(bind_level='SB')                      AS has_sb,
       BOOL_OR(bind_level='WB')                      AS has_wb,
       COUNT(*)                                      AS n_alleles
  FROM netmhc_score
 WHERE peptide = ANY([250 sequences])
 GROUP BY peptide
```

实测性能：250 sequence 查 6.4 秒，匹配 198/250（其余 52 个肽长度不在 10-30 aa 范围内，netMHCIIpan 不预测）。

### 4.4 跨功能去混淆（提案 §4.2 启发式）

**核心公式**：`aip_specific = aip_imfp_rank − max(other_function_rank)`

```python
other_cols = {
    "antiox":   "aopxsvm",
    "antibac":  "amp-esm",
    "imfp_acp": "imfp_lg_ACP",
    "imfp_adp": "imfp_lg_ADP",
    "imfp_ahp": "imfp_lg_AHP",
    "imfp_amp": "imfp_lg_AMP",
}
other_pct = {short: df[col].rank(pct=True) for short, col in other_cols.items()}
df["other_max"] = pd.DataFrame(other_pct).max(axis=1)
df["aip_specific"] = df["aip_imfp"].rank(pct=True) - df["other_max"]
```

**关键局限**（与提案 §4.2 期望的偏差）：

- 抗黑素 2 个通道（`blsam_tip_lr/gbm`）缺失 → 实际只能用 6 个跨功能通道（提案期望 8 个）
- 缺失的"抗黑素贡献"无法显式扣减——但 iMFP-LG ACP/ADP 通道与抗黑素在功能上有部分重叠（抗氧化肽常被预测为抗糖尿病肽），可能间接覆盖一部分
- 这是工程上的次优解，必须如实登记在文档里

### 4.5 性能对比

| 方案 | 时间 | 备注 |
|---|---|---|
| 提案照搬（18 个相关子查询 20M 行） | 30+ 分钟 / OOM | 失败 |
| 全表 enrich（每个 tool 拉 20M 行） | 30+ 分钟（无 vacuum） / 1.7s（有 vacuum） | 不稳定 |
| **250-id 主键 enrich + netmhc_score 独立查 + 跨功能去混淆** | **40.3 秒** | 选中方案 |

## 5. PG 性能的两个关键 SET

```sql
SET enable_seqscan = off
SET enable_bitmapscan = off
```

`peptide_enrichment` 表 97 GB、planner cost 估算常常失误（实测代价被低估 1000×）。强制走 `(tool, score DESC NULLS LAST)` 索引扫，否则会陷入 seq scan 或 bitmap heap scan。

实测对比（v1 跑完后复验，VACUUM 状态已恶化、较抗菌 v1 慢）：

| 查询 | 默认 plan | 强制 plan |
|---|---|---|
| `WHERE tool='imfp_lg_AIP' AND score >= p90`（2M 行） | bitmap heap scan，超时 | index scan **15.6s** |
| `WHERE tool='bepipred3' AND peptide_id = ANY(250)` | bitmap heap scan，14.8s | index scan **14.8s**（VACUUM 缺失下仍较慢） |
| 其他 11 个 tool × 250 id | < 0.5s | — |
| `netmhc_score WHERE peptide = ANY(250)` | peptide 索引 | 6.4s |

## 6. AGGRESCAN a3v 一维实现（沿用 antioxidant）

与 antioxidant/antibacterial 方向完全相同：a3v(sequence) = mean(a3v_i)，a3v_i 来自 Conchillo-Solé 2007 论文的氨基酸级别表。

154 条肽 × ~30aa = 4620 次字典查，< 30ms 完成。

## 7. Winsorized std 权重（README §三"权重数据驱动"）

```python
def winsorized_std(s, lo=0.05, hi=0.95):
    return s.clip(s.quantile(lo), s.quantile(hi)).std()
```

实测结果（Top 通道的 87 条通过肽）：

| 分量 | 区分度（Winsorized std） | 归一化权重 |
|---|---|---|
| aip_specific | 0.2357 | **0.247**（最高）|
| cpp     | 0.0970 | 0.102 |
| sens    | 0.2225 | 0.233 |
| epitope | 0.2157 | 0.226 |
| agg     | 0.1822 | 0.191 |
| **Σ** | — | **1.0000** |

**与另三方向对比**：

- 本方向 `aip_specific` 权重 0.247（最高）—— 因为它是唯一能区分抗炎的信号
- 本方向 `cpp` 权重 0.102（最低）—— 因为 Top 通道里 PLM4CPPs 命中数很低（87 条肽 plm4cpps 中位数低）

## 8. 综合分计算（含递送调权）

```python
DELIVERY = {
    'topical':     {'cpp':1.4, 'sol':1.3, 'thermal':0.7, 'immuno':'normal'},
    'nano':        {'cpp':0.7, 'sol':1.4, 'thermal':1.0, 'immuno':'normal'},
    'microneedle': {'cpp':1.0, 'sol':1.4, 'thermal':1.4, 'immuno':'normal'},
    'injection':   {'cpp':1.0, 'sol':1.0, 'thermal':1.0, 'immuno':'tight'},

score = Σ(w_k * comp_k * mult_k) * α      if passed_safety and immuno_passed_injection

```

`immuno='tight'` 在 injection 下落地为 `mhcflurry ≥ 0.35 → 0 分` 或 `netmhcipan_has_sb=True → 0 分`。

## 14. 已知工程遗留

| # | 遗留 | 影响 | 建议 |
|---|---|---|---|
| 1 | aip_v5 / aip_esm2 完全不在 DB | L1→L2 级联无法实现；唯一可用抗炎模型有训练泄漏 | 上线 aip_v5 + aip_esm2（提案 §附 升级路径 4 已建议）|
| 2 | BLSAM-TIP 双模型缺失 | 抗黑素跨功能去混淆缺失 | 上线重建版（与 antimelanin v1 一致）|
| 3 | imfp_lg_AIP 训练集实际上限约 25 aa | 26-30 桶分层 Top-K 无条可取 | 收窄长度硬约束到 [11, 25]（参数调整）|
| 4 | bepipred3 查询慢（14.8s） | 整体耗时大 | VACUUM peptide_enrichment；加每周 cron |
| 5 | 抗黑素 BLSAM-TIP 缺失 | 跨功能去混淆仅 6 通道（提案期望 8）| 上线 BLSAM-TIP 后即可补齐 |
| 6 | Top 87 条的综合分是基于小样本 | 权重可解释性弱 | 通过上线 aip_v5/aip_esm2 增加通过数 |
| 7 | aip_specific Top 中位数 -0.32（多数肽"抗炎特有信号"为负） | Top 多数肽更像"通用功能肽" | 这是 imfp_lg_AIP 结构性缺陷的实证 |
