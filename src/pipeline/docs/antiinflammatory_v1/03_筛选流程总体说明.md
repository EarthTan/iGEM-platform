# 抗炎方向 · 筛选流程总体说明（生物学汇报版）

> 受众：生物学 / 湿实验团队，不写代码。
> 对应提案：`docs/proposal/管线-抗炎.md` §1–§8。
> 本方向 **WIP**（与抗黑素方向并列），不可直接进入湿实验阶段。

---

## 1. 我们在做什么

iGEM 平台抗炎方向的目标：从 2,025 万肽库中筛出"最可能抗炎"的功能肽短名单，交付给湿实验团队做 NF-κB 抑制、T 细胞增殖、溶血、致敏等验证。

## 2. 三道硬约束（提案 §0 + §2）

任何被纳入候选池的肽必须同时满足：

1. **长度 ∈ [11, 30] aa**（提案 §2 硬约束）—— 团队的 OOD 实测：≤10 aa 的肽在 AIP 模型上 AUC 0.498（随机），分数不可信。本库 99.74% 的肽本来就在 [11, 30] 范围内，损失极小。
2. **毒性 < 0.38**（ToxinPred3 硬门控）—— 高毒性肽直接淘汰。
3. **溶血 < 0.55**（HemoPI2 硬门控）—— 高溶血肽直接淘汰。

**软门控**（NULL 默认放行）：
- MHC-I 结合（MHCflurry，< 0.50 通过；仅 5-15 aa 评估）
- MHC-II 结合（netMHCIIpan SB，硬门控；任一 allele 为 SB 即淘汰；从独立表 `netmhc_score` 接入）

## 3. 候选池

候选池 = imfp_lg_AIP P90+ 且 length ∈ [11, 30] 的肽，共 **2,024,889 条**（与抗氧化/抗菌完全一致）。

**为什么候选池选 imfp_lg_AIP？**

提案 §1 列了三个 AIP 模型：
- `aip_v5`（AIP-iFeature-LightGBM v5）
- `aip_esm2`（AIP-ESM2 v8）
- `imfp_lg_AIP`（iMFP-LG 多标签分类器的 AIP 通道）

我们用 `check_score_coverage_aip.py` 核对 DB，发现：

| 模型 | 提案预期 | DB 实际 |
|---|---|---|
| `aip_v5` | 全量（须核对）| ❌ **0 行** |
| `aip_esm2` | 全量（须核对）| ❌ **0 行** |
| `imfp_lg_AIP` | 全量 | ✅ **全 20.25M** |

**`aip_v5` 和 `aip_esm2` 完全不在 DB**——这是本方向最重要的发现。

提案 §3 的"L1→L2 级联"（L1=`aip_v5` 粗筛、L2=`aip_esm2` 精排）因此**完全无法执行**。工程上退化为 `imfp_lg_AIP` 单信号排序：既当候选池 cutoff，又当综合分主信号。

## 4. 唯一可用抗炎功能模型的局限（提案 §0）

`imfp_lg_AIP` 是 iMFP-LG 多标签分类器的抗炎通道。它的优点是全 20.25M 覆盖，缺点是：

1. **训练泄漏**：iMFP-LG 的训练集与测试集 100% 重叠，分类器在独立测试集上性能严重虚高。
2. **碎片盲点**：iMFP-LG 在"非功能肽碎片"（C 类）上的 AUC 仅 0.107——碎片反而被预测为高抗炎。
3. **功能 vs 抗炎混淆**：iMFP-LG 把"功能肽"（不论功能）都打高分——它测的是"这条肽像不像一个功能肽"，不是"这条肽抗不抗炎"。

这是本方向"只能做到最佳状态而不是 READY"的核心原因。

## 5. 启发式：跨功能去混淆（提案 §4.2）

虽然 iMFP-LG 测的是"功能肽"而非"抗炎"，但可以做一个启发式：**扣掉"该肽像通用功能肽"的部分，剩下的才是抗炎特有信号**。

公式：
```
aip_specific = aip_imfp_rank − max(other_function_rank)
```

其中 `other_function_rank` 是该肽在其它功能通道（抗氧化/抗菌/iMFP-LG 五通道）上的 rank pct 最大值。

**直觉**：如果一条肽在 AIP 高分，且**没有任何**其它功能模型把它认领，那么它"像抗炎"的部分更不可能被"像通用功能肽"解释 → 更可能是真抗炎信号。

**实际可用通道数 6**（提案期望 8）：
- ✅ `aopxsvm`（抗氧化）
- ✅ `amp-esm`（抗菌）
- ❌ `blsam_tip_lr`（抗黑素 LR）—— 缺失
- ❌ `blsam_tip_gbm`（抗黑素 GBM）—— 缺失
- ✅ `imfp_lg_ACP/ADP/AHP/AMP`（iMFP-LG 五通道）

**必须承认**：这是启发式，不是经过验证的抗炎判定。

## 6. Top/Bottom 选取

1. 从候选池 2,024,889 条按 `aip_imfp` 降序取 Top 150、按升序取 Bottom 100。
2. 对 Top + Bottom 共 250 个 peptide_id，在 12 个工具上查分（含主键 enrich + netMHCIIpan 独立表）。
3. 对每条肽算 `aip_specific = aip_imfp_rank − max(other_function_rank)`。
4. 安全门控（4 项）剔出有问题的肽：
   - 毒性 ≥ 0.38
   - 溶血 ≥ 0.55
   - MHC-I ≥ 0.50（MHCflurry，软门控）
   - netMHCIIpan 任一 allele 为 SB（硬门控）
   - length ∉ [11, 30]（冗余检查）
5. 剩余肽通过 → **分层 Top-K**：每个长度桶各取 K，合并成 Top 150。
6. 排名（用 composite_topical 全局排）。
7. 落 constructs 表（status='WIP'，scenario='inflammation'）。

## 7. 综合分（composite）

对每条通过安全门控的肽，计算 5 个分量（归一化到 [0,1]）：

| 分量 | 含义 | 方向 |
|---|---|---|
| **aip_specific** | 跨功能去混淆后抗炎特有信号 | 越高越好 |
| cpp | 穿膜倾向（pLM4CPPs）| 越高越好 |
| sens | 致敏性（AlgPred2）| 越低越好 → 翻转 |
| epitope | B 细胞表位（BepiPred-3.0）| 越低越好 → 翻转 |
| agg | 聚集倾向（一维 AGGRESCAN）| 越低越好 → 翻转 |

权重 = 各分量的 Winsorized std（区分度高的自动升权）。

实测（Top 87 条）：
- aip_specific: 0.247（最高）
- cpp: 0.102（最低）
- sens: 0.233
- epitope: 0.226
- agg: 0.191

然后对 4 种递送方式各算 composite = Σ(w_k × comp_k × mult_k) × α：

| 递送 | 乘数（CPP/溶解度/热稳定）|
|---|---|
| 外用 | 1.4 / 1.3 / 0.7 |
| 纳米载体 | 0.7 / 1.4 / 1.0 |
| 微针 | 1.0 / 1.4 / 1.4 |
| 注射 | 1.0 / 1.0 / 1.0（**免疫收紧**：MHC-I ≥ 0.35 或 MHC-II SB → 分置 0）|

## 8. 落库结果

**154 条 construct 落库**（status='WIP'），其中：
- Top 通道：87 条（功能分最高）
- Bottom 通道：67 条（功能分最低，作为对照）

每条 construct 包含：
- 完整序列（`[backbone_name] | [linker] | [peptide]` 占位拼接）
- 18 项基线分（`scores` JSONB）
- 4 种递送综合分（`delivery_scores` JSONB）
- `func_score_meaning = 'ranking_only_not_probability'`（WIP 标志）
- `assessed_hemo/mhci/mhcii` 评估/未评估标记

## 9. 为什么是 WIP 而非 READY

提案 §0 已经把"为什么只能做到最佳状态"讲清楚了：

> **AIP 三模型均无法区分抗炎与其他功能肽（C vs A ≈ 0.5），本名单为『功能肽样 + 跨功能去混淆后』的启发式候选，需湿实验确认。**

**本管线比提案 §0 描述的更严重**：不仅三个 AIP 模型都不能区分抗炎 vs 其他功能，其中两个（`aip_v5` / `aip_esm2`）**完全不在 DB**。唯一可用 `imfp_lg_AIP` 有训练泄漏 + 碎片盲点。

**aip_specific Top 中位数 = -0.32**（Top 多数肽"抗炎特有信号"为负），是模型缺陷的实证——Top 多数肽更像"通用功能肽"，抗炎特有信号是负的。

**湿实验启动条件**（提案 §8 升级路径）：
1. **上线 `aip_v5` 和 `aip_esm2`**（独立 AUC 0.80-0.90）—— 这是把本方向从 WIP 转 READY 的**唯一正路**
2. **上线 BLSAM-TIP 重建版**——补齐抗黑素跨功能去混淆通道
3. **用湿实验标签做 Platt 缩放校准 imfp_lg_AIP**——让 imfp_lg_AIP 输出可解释

## 10. 与另三方向的关系

- **抗氧化（READY）**：候选池 2.02M，Top 113 通过安全门控（75.3%），落库 170 条。
- **抗菌（READY）**：候选池 2.02M，Top 7 通过安全门控（4.7%），落库 65 条。
- **抗黑素（WIP）**：唯一可用 TIPred 99.5% 阳性无富集力，落库 107 条。
- **抗炎（WIP，本方向）**：唯一可用 imfp_lg_AIP 有训练泄漏，落库 154 条。

四个方向共用同一 `constructs` 表（direction 字段区分），界面与预计算库均标 WIP 的方向不与 READY 方向并列展示。

## 11. 一句话总结

> **抗炎方向已用现有工具做到了最好**：用 iMFP-LG AIP 单信号 + 6 通道跨功能去混淆 + 4 项安全门控，产出 154 条 WIP 候选（Top 87 + Bottom 67），全部进入 `igem_peptides.constructs` 表。但因为唯一可用抗炎功能模型有结构性缺陷（训练泄漏 + 碎片盲点），这些候选**不是"已筛出的抗炎肽"**，而是"按 iMFP-LG 弱信号排出的待湿实验验证短名单"。**要真正 READY，必须上线 aip_v5 和 aip_esm2**。
